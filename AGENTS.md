## Engineering judgment and proactive refactoring

- This is a reusable plugin for multiple users and inverter models, not a private integration for the user's installed inverter. Never hardcode that inverter's hardware model into accessory metadata or assume all users have its register map. Use consistent generic model metadata unless the actual model is reliably detected or explicitly configured. Keep model-specific validation observations separate from claims of supported models; broader register-map support must be implemented and verified before being advertised.
- The user provides objectives; technical suggestions in their questions are not instructions to follow mechanically. Evaluate performance, transferred data, reliability, and complexity, then choose a balanced solution and briefly explain the tradeoffs. Do not turn "why not read everything at once?" into a permanent requirement for exactly one request. If a suggestion is less suitable, explain why and implement a reasonable approach within the authorized scope.
- Proactively refactor source when needed for clarity, maintainability, reduced duplication, or correct implementation of the current feature. Refactoring alone does not require asking again.
- Match the scope to the actual problem. Preserve agreed behavior and conventions unless the current requirement calls for a change. Refactoring does not authorize deployment, device pairing, or inverter configuration changes.
- After every code change, run typechecking and the relevant tests before reporting completion; do not stop at writing tests or assume earlier passing results cover later edits. Fix failures and rerun affected checks. For Matter endpoint topology, initialization or cache changes, also run the simulated-network Matter integration suite; calling an initializer with a mocked endpoint does not verify its lifecycle. Report what actually ran and any remaining verification limits. Briefly explain what was refactored and why.

- Current polling decision (2026-11-01): sequential compact groups 90-91, 109-112, 150, 157-160, 169, 178-191 (26 words) for full measurements. No energy registers are polled. --grid-only reads 150. Respect FC03 limits and preserve group-level error isolation.

These are observations from a small sample, not performance guarantees. Prefer nearby groups because measured latency was similar, less unused data is transferred, and a failed group does not invalidate every measurement. The fewest requests are not automatically the best overall solution. Respect the FC03 maximum of 125 registers.

- Use consistent electrical accessory names: PV1 Power, PV2 Power, Grid Power, Load Power and Battery Power. Preserve existing sensor keys and UUIDs when renaming.
- The user explicitly selected separate PV1/PV2 and W, A, V for PV1, PV2, Grid, Load (house load) and Battery on 2026-11-01. This replaces the earlier total-PV-only and cumulative-energy requirements. Keep temperature and battery SOC. The user restored Grid contact on 2026-11-01 alongside Grid Power because Apple Home shows power but apparently not current/voltage. Keep its sensorKey=grid and cached UUID; use register 150 with the original hysteresis (present at >=100 V, remain present at >=80 V), true=closed/present. Failed reads mark it unreachable, never report an outage from a read error. Share the existing voltage read with Grid Power. Remove the derived grid/contact CLI fields; --grid-only remains a voltage-only diagnostic. A zero active power does not imply grid outage; voltage indicates presence, not relay connection or grid quality.
- Single-phase hybrid register mapping: PV1 W/V/A = 186/109/110, PV2 = 187/111/112; PV voltage/current scale 0.1 V/A. Grid total power 169 (positive import, negative export), voltage 150 at 0.1 V, internal L1 current 160 at 0.01 A. Load total power 178, L1 voltage 157 at 0.1 V, L1 current 179 at 0.01 A. Battery power 190, voltage 183 at 0.01 V, current 191 at 0.01 A; positive output/discharge, negative charge. These are single-phase map choices, not universal model support. Grid data is internal metering, not the external CT (170-172). Load scope depends on wiring/meter configuration and must be compared against the inverter.
- Read reported power directly, never derive active AC watts from V times A. Power and current for Grid/Load/Battery are signed int16; 0xffff is -1 on signed registers, not an unavailable sentinel. Unsigned PV power/voltage/current and battery/grid/load voltages use 0xffff as unavailable. Zero is valid. Read failure yields null for affected attributes without discarding independent values.
- Each branch is one ElectricalSensor; PV1/PV2/Battery use DC mode and Grid/Load use AC mode. Matter uses mW/mV/mA; CLI/logs use W/V/A. No PowerSource is added to these electrical endpoints; SOC remains scoped to Battery Temperature.
- Preserve the current log file by appending when updating a running CLI. Do not start or replace a background CLI unless requested.
